# HANDOVER — comedy compiler (2026-10-07)

## What was built
`comedy/` — the comedy compiler from the architecture plan: teach
Freaktown how comedy behaves in TIME, not what it says. Persona stays
Freaktown-native; corpus compiles into timing that feeds delivery.v1.

```
comedy/corpus.py      written set → anonymous structural/timing grammar
                      (mechanism, beat types, durations; NO original text
                      emitted — source_hash only)
comedy/rhythms.py     5 archetypes: dry_misdirection, manic_escalation,
                      awkward_character, rapid_tags_v3, callback_waltz —
                      fits()/rank()/pick() against rhythm_features()
comedy/director.py    bit + VIBE profile → freaktown.delivery.v1,
                      schema-validated (contracts/delivery.v1.schema.json).
                      Per-line beat classification (multi-sentence lines
                      can't swallow the punch), punch guarantee, pauses
                      from rhythm × character (TTS never owns timing)
comedy/evaluator.py   predict() heuristic laugh/groan scores with reasons;
                      learn() aggregates real reaction events (jsonl) into
                      per-mechanism latency/strength stats — ranker hooks in
                      behind the same API later
comedy/__init__.py    analyze / compile_delivery / predict / learn
tests/unit/test_comedy.py   8 tests, all passing
```

## Decisions worth keeping
- **Anonymous by design**: corpus output never carries the source text, only
  structure — safe to ingest third-party material.
- **delivery.v1 stays frozen**: director emits exactly the schema contract
  (beat type enum, pause limits); no silent v1 mutations.
- **Punch guarantee** mirrors corpus._classify: a set without a punch gets
  the pre-closer line promoted, in delivery too.
- **Character fit**: rhythm punch_hold blends with the character's own
  punchline_hold_ms — the personality still wins over the archetype.
